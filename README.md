# Ghalem Store Pro — متجر غالم الاحترافي لشحن الألعاب

متجر إلكتروني متكامل (واجهة + خادم + قاعدة بيانات) لبيع باقات شحن الألعاب بالدينار الجزائري،
مع دفع يدوي عبر CCP/BaridiMob يتحقق منه المالك بنفسه، ولوحة إدارة محمية.

**الحالة:** المشروع مكتمل ومُختبَر محليًا (34 اختبارًا آليًا ناجحًا).
**ليس منشورًا على الإنترنت بعد** — النشر خطوة خارجية يقوم بها المالك (القسم 5).

---

## 1. لماذا هذه التقنيات؟

| القرار | التبرير |
|--------|---------|
| Node.js + Express | لغة واحدة للواجهة والخادم، منظومة خفيفة، يعمل في كل مكان |
| **SQLite** (مدمجة في Node 22+ عبر `node:sqlite`) بدل PostgreSQL | متجر لمالك واحد: ملف واحد = قاعدة البيانات كاملة. صفر إعداد، صفر خدمات إضافية، النسخ الاحتياطي = نسخ ملف، وتعمل على أي VPS. لحجم هذا المتجر (مئات الطلبات يوميًا) SQLite كافية تمامًا |
| scrypt (مدمج في Node) للكلمات | خوارزمية تجزئة مخصصة لكلمات المرور، بلا مكتبات خارجية |
| express-session + مخزن SQLite | الجلسات تبقى بعد إعادة تشغيل الخادم |

**طريق الترقية إلى PostgreSQL** (إذا كبر المتجر لاحقًا): طبقة قاعدة البيانات معزولة في
`server/db.js` — كل الاستعلامات عبارات مُجهّزة (prepared statements) بعلامات `?`
متوافقة مع postgres. الترقية = استبدال `db.js` بعميل `pg` + تحويل أنواع الأعمدة
(TEXT→VARCHAR/TIMESTAMPTZ) + تشغيل نفس الـ migrations بصيغة postgres. لا يلزم تغيير
الـ routes.

## 2. التشغيل محليًا

```bash
cd ghalem-store-pro
npm install
cp .env.example .env
# ولّد SESSION_SECRET وضعه في .env:
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

npm run migrate   # إنشاء الجداول
npm run seed      # الألعاب والباقات والأسعار والإعدادات (عناصر نائبة)
npm run create-admin   # إنشاء حساب المدير الأول (تفاعلي)
npm start         # http://localhost:3000
```

ثم افتح:
- المتجر: http://localhost:3000
- لوحة الإدارة: http://localhost:3000/admin

## 3. إنشاء حساب المدير الأول

```bash
npm run create-admin
```

سيطلب اسم المستخدم وكلمة المرور (≥ 10 أحرف). تُخزّن الكلمة مجزأة بـ scrypt —
**لا تُخزّن ولا تُرسل أبدًا كنص صريح**. لا يوجد حساب افتراضي في الكود.

## 4. الإعدادات المهمة (بعد أول دخول للإدارة)

من لوحة الإدارة ← **الإعدادات**، أدخل القيم الحقيقية (الكود يحوي عناصر نائبة فقط):
- `whatsapp_number` — رقم الواتساب بالصيغة الدولية (213...)
- `pay_ccp_number` / `pay_baridimob_number` — أرقام الحسابات الحقيقية
- `payment_instructions_ar` — تعليمات الدفع للزبائن
- `store_name` / `support_text`

## 5. النشر على الإنترنت (يعمل 24/7)

### الخيار الأسهل: Railway أو Render
1. ادفع المشروع إلى مستودع Git خاص.
2. أنشئ خدمة جديدة من المستودع (Build: `npm install`, Start: `npm start`).
3. أضف متغيرات البيئة: `SESSION_SECRET` (عشوائي طويل)، `NODE_ENV=production`.
4. أضف **قرصًا دائمًا (Volume)** مربوطًا على `/app/data` — بدونه تضيع قاعدة البيانات عند كل إعادة نشر.
5. فعّل النطاق + HTTPS من لوحة المنصة (مجاني).

### الخيار الأقوى: VPS + Docker
```bash
# على الخادم: ثبّت Docker ثم:
echo "SESSION_SECRET=$(node -e \"console.log(require('crypto').randomBytes(48).toString('hex'))\")" > .env
docker compose up -d --build
```
- قاعدة البيانات والإيصالات في مجلد `./data` (يبقى بعد التحديثات).
- للنطاق وHTTPS: ضع Nginx/Caddy أمام الحاوية (Caddy يمنح شهادات تلقائية).

**ملاحظة أمان:** التطبيق نفسه لا ينهي TLS — HTTPS مسؤولية المنصة/الوكيل العكسي. لا تنشر بدون HTTPS.

## 6. سير عمل الطلب والدفع اليدوي

1. الزبون يختار الباقات → يُدخل **معرّف لاعب مستقل لكل لعبة** → ينشئ النظام طلبًا برقم فريد وإجمالي **محسوب على الخادم**.
2. تظهر تعليمات الدفع (من الإعدادات). يبقى الطلب `بانتظار الدفع`.
3. الزبون يُدخل **مرجع التحويل** (+ صورة إيصال اختيارية) → يصبح `قيد مراجعة الدفع`.
4. **أنت** تتحقق من التحويل في حسابك/سجلاتك الرسمية، ثم من لوحة الإدارة: **قبول** (مدفوع) أو **رفض** (مع سبب) أو **إرجاع للمراجعة**. يُسجَّل اسمك ووقت الإجراء.
5. بعد التأكد: غيّر الحالة إلى `تم الشحن` بعد شحن الرصيد فعليًا.

> **قاعدة صارمة:** الطلب لا يُعتبر مدفوعًا لمجرد رفع إيصال. لا يوجد أي تكامل آلي مع BaridiMob/CCP.

## 7. النسخ الاحتياطي والاستعادة

```bash
# نسخ احتياطي (SQLite = ملف واحد):
sqlite3 data/ghalem-store.db ".backup 'backup-2026-10-20.db'"
# أو ببساطة: انسخ data/ghalem-store.db + data/uploads/

# استعادة: أوقف الخادم، انسخ الملفات مكانها، شغّل الخادم.
```

يُنصح بنسخة يومية آلية (cron على الخادم) + الاحتفاظ بنسخة خارجية.

## 8. الاختبارات

```bash
npm test   # 34 اختبارًا — تفقّد tests/ للتفاصيل
```

**ما تم اختباره فعلًا:** طلب متعدد الألعاب بمعرفات مستقلة، رفض التلاعب بالأسعار،
رفض المدخلات غير الصالحة، منع الإرسال المكرر، دورة الطلب الكاملة (قبول/رفض يدوي)،
مصادقة الإدارة (كلمة خاطئة/غير مسجل/قفل الحساب)، تسجيل الخروج، بقاء البيانات بعد
إعادة التشغيل، الخصومات الحقيقية (تفعيل/انتهاء)، خلو الإعدادات العامة من الأرقام الحقيقية.

**ما لم يُختبر:** حدود المعدل (عمدًا — لتفادي تلويث الاختبارات)، سباق الإرسال المتزامن،
سلوك المتصفح الفعلي (لا متصفح آلي في بيئة البناء)، رفع ملفات خبيثة حقيقية.
